# Specs

Cada feature usa `spec.md → plan.md → tasks.md`.

Las specs **no sustituyen** `docs/00_SOURCE_OF_TRUTH.md`. Solo detallan requisitos dentro de sus límites.

Reglas:

1. `spec.md` describe comportamiento, restricciones y acceptance criteria.
2. `plan.md` elige componentes ya autorizados por la Source of Truth.
3. `tasks.md` divide trabajo en unidades pequeñas y verificables.
4. Un cambio arquitectónico se tramita primero como ADR.
